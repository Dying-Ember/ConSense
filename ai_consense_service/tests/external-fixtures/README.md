# External fixture tests

The publication snapshot preserves five Java test files under java/ with their original package declarations, source and assertions unchanged after Git line-ending normalization. This directory is outside Maven's default src/test/java source root.

The tests require private uploaded correspondence, actual experimental/runtime captures, or original competition templates and renderer assets that are intentionally absent from this repository. Their removal from the default test source root is a publication boundary, not deletion of the test implementation and not a claim that these tests passed without their data.

The external fixture set includes:

- drafting/original-2c: original uploaded correspondence DOCX files.
- drafting/harness/a10-replay/trace.json: actual runtime/model replay capture.
- drafting/a10/captured-sim08-response.json and captured-sim08-source.txt: actual experimental response/source captures.
- DraftingMultilineBodyIntegrationTest: original NTT, SCT and SCC DOCX templates supplied through -Dconsense.acceptance.sourceDir, using the filenames asserted in the test; optional -Dconsense.acceptance.bodyEvidence stores observations.
- DraftingNativeLayoutIntegrationTest: original NTT-source.docx, SCT-source.docx and SCC-source.docx supplied through -Dconsense.acceptance.bindingSourceDir, plus the existing full-reference input JSON via -Dconsense.acceptance.fullReferenceInputs. Its real desktop renderer requires -Dconsense.acceptance.desktopExecutable, -Dconsense.acceptance.desktopAssetRoot and -Dconsense.acceptance.desktopFontCache; -Dconsense.acceptance.layoutWorkRoot and -Dconsense.acceptance.layoutEvidence select unversioned renderer work and observation directories. These are actual-original and real-renderer acceptance tests; simulated replacement documents or relaxed assertions do not satisfy them.

VettingCurrentPythonWireTest, VettingProbeTimingTest, VettingRetrievalHealthTest, VettingRetrievalSourceUnitsTest and VettingStrictHybridTest now remain together in Maven's default src/test/java source root. Their src/test/resources/vetting/current_window_health.json is frozen protocol metadata fixture derived from a historical runtime snapshot, not a fresh health measurement. These mocked protocol tests do not establish current model readiness, vector database health, retrieval precision, or OCR quality.

The default Java/Python loopback protocol suite requires a Python environment with the dependencies declared in tools/vetting_eval/requirements.txt. Prepare that environment separately; a system Python executable alone does not establish that the dependencies are installed. WireFixtureTestSupport uses the service's .venv interpreter when present, or the explicit -Dconsense.test.python=<interpreter> / CONSENSE_TEST_PYTHON setting, before falling back to python on Windows or python3 elsewhere. The fixture imports the current Python runtime but forbids neural forward, tokenizer loading, vector database operations and OCR; its final counters must remain zero for those operations. No model weights or real model API calls are required by these protocol checks.

The first synchronization-wide test run exposed missing explicit mock profile endpoints, missing original-template/renderer inputs, the system Python's missing FastAPI dependency, and a Windows CRLF checkout of a SHA-bound native-text fixture. Mock tests now declare their own TEST ONLY endpoints; actual-original tests are preserved here; the Python interpreter is an explicit environment prerequisite; and the SHA-bound fixture is kept in its original Git LF form. None of these changes relaxes evidence, SHA or original-layout assertions.

To run this group, prepare an isolated, unversioned test workspace with authorized external fixtures matching the source snapshot. Copy this directory's Java package tree into that workspace's src/test/java and restore fixture paths under that workspace's src/test/resources or pass the explicit original-template and renderer properties above. Run the tests there; do not commit uploaded correspondence, model outputs, fresh health captures, credentials, renderer assets, or restored private fixtures to the publication repository.

The retained a10 replay source DOCX files are explicit fictional TEST ONLY documents. The retained correction03 pagination-value fixture is simulated with rejected-output provenance. The retained legacy diagnostic serialization fixture is deterministic synthetic/mock data, with no network, credentials, or corpus. These are not historical project evidence.

The initial publication verification covered source compilation, 13 passing rule tests and four skipped native guard cases. Current synchronization verification is recorded in repository-root SOURCE-INTEGRATION.json and docs/PRIVATE-REPOSITORY-SYNC.md; SOURCE-SNAPSHOT.json records only the initial import. Neither default-suite success nor this publication boundary reruns the five external tests or establishes real model/OCR/retrieval/PDF provider acceptance.
