## Public interface and adoption contract

```java
DocxTemplateEditor editor = new DocxTemplateEditor();
TemplateIndex source = editor.inspect(originalDocxBytes);
Paragraph p = source.mainParagraph(484); // one-based descendant w:p, including tables
Edit adopted = Edit.replaceCatalogSpan("bond", p,
    p.getCatalogText().indexOf("*G1/*G1a"),
    p.getCatalogText().indexOf("*G1/*G1a") + "*G1/*G1a".length(),
    "*G1/*G1a", "G1a");
DocxEditResult generated = editor.apply(originalDocxBytes,
    new SourceEditBatch(source.getSourceSha256(), Collections.singletonList(adopted)));
```

The example uses a known actual source token. The caller must establish unique matching and adoption; the utility never searches for a business decision, selects an alternative or invents missing values. The real contact/rate test uses conspicuously synthetic values to exercise mechanical preservation, not contractual facts.

- `TemplateIndex`: source/package SHA256; main and story paragraph lists; `mainParagraph(oneBasedOrdinal)`; `paragraph(id)`; source-bound p/tc/tr/tbl/sectPr anchors; original entry hashes; paired/unpaired bookmark and field inventory, sections and native OMML.
- `Paragraph`: original part, locator, ordinal, serialized subtree SHA256, cell/row/table/section identities, editable text, catalog text and direct run/style metadata. Header/footer/footnote/endnote paragraphs are inspectable; A07 edits only `word/document.xml`.
- `Edit`: `replaceSpan`, `replaceCatalogSpan`, optional explicit `withStyleDonor(RunInfo)`, `clearParagraph`, `clearEditorialCell`, `deleteParagraph`, `deleteRow`, explicit `removeNodes` (p/tr/tbl), and `insertParagraphs` before/after a source paragraph with an explicit source paragraph style donor and a list of lines.
- `SourceEditBatch`: exact current input package SHA256 plus immutable typed edits. Every operation has a unique ID and exact paragraph/cell/row/node hash expectation. Span expectation is exact original text. All targets and feature/overlap/remaining-cell/row checks resolve before mutation; a rejection returns no artifact and does not alter the input byte array or any previous output.
- `DocxEditResult`: defensive byte copies, generated package hash/index, original input hash, untouched-entry hashes, applied operation ledger and feature impacts. Ledger includes source/generated hashes, action, span expectation/result, source donor identity/hash, insertion lines, original target identity/hash, generated target locator/hash or removal, and retained-last-cell-paragraph disposition. The caller can bind the next body edit to the returned generated index/hash; old locators/hashes are not silently reinterpreted.

`Paragraph.getText()` uses UTF-16 offsets and includes actual tabs and line/page breaks. It excludes paragraph tab settings and run properties. `getCatalogText()` concatenates only descendant `w:t`, matching the verified source catalog. `replaceCatalogSpan` validates the catalog substring, maps it through actual text nodes and rejects any adopted span crossing a control or unsafe inline feature. A catalog offset must never be used directly as an editable offset. A tab before a selected token is preserved and shifts the mapped editable start; a tab inside the selection is explicitly unsupported.

Stable IDs are `part#/<qualified element path with one-based sibling ordinals>`, including `[1]` components. They refer to the batch's exact source package; structural changes can alter generated paths. Index hashes use the utility's deterministic XML serialization, not the audit's lxml C14N algorithm. A08 must validate its curated guidance sidecar by exact source hash, original ordinal, expected text and structural role, then obtain the editor's own node/hash guard. It must not compare unlike hash algorithms or assume literal XPath strings omit `[1]` in the same way.

## Preservation behavior

No-op returns the complete original ZIP bytes. Edits copy every untouched entry's uncompressed payload without a POI/Word/LibreOffice round trip; only `word/document.xml` is reserialized. ZIP container compression/timestamps and modified XML lexical serialization may differ. Existing pPr/rPr, numbering definitions, table grids/widths/borders/merges, sections, relationships, document properties and header/footer entries are retained. Existing native math stays native.

Default span replacement changes only covered `w:t` values across existing direct runs; unselected prefixes/suffixes and all run properties remain. An explicitly source-bound replacement style donor creates a bounded styled run and retains original prefix/suffix styling, tabs and nontext children. Word `proofErr` spelling/grammar markers are known zero-width metadata: they remain in place while a split text span may cross them. Contractual bookmark boundaries and opaque features remain protected.

Editorial cell and paragraph clears empty only selected descendant `w:t`; they keep paragraphs, runs, rPr/pPr, tabs, breaks, bookmarks, native math and grid topology. A cell clear requires an explicit source cell anchor and rejects nested tables. No font/italic/delete-text heuristic selects guidance. Noncontiguous preparer notes require individually selected paragraphs; a numeric interval cannot imply deleting interleaved formal text.

Paragraph/node/row removal is a stronger explicitly adopted operation. Other cells of a shared row are protected when only one paragraph is selected. Rows with vertical merges and removal of the final table row reject. Explicit whole-table removal is supported through `removeNodes` when its complete bounded scope is adopted. If all direct paragraphs of a retained cell are selected for removal, one original paragraph is text-cleared to keep a valid cell; its formatting/controls remain and the ledger states that disposition. Partial bookmark or complex field boundary removal rejects atomically.

Insertion clones the adopted donor's pPr and first direct source run's rPr. Lines become separate paragraphs; a tab inside a line becomes a native tab. No cover, title, contract-number line, font pack or new template design is introduced.

Field manifests distinguish removed scopes, changed/cleared text with preserved bookmark anchors, removed reference targets and pagination review. Bookmark impact checks the actual selected text against the paired range, including ranges spanning several paragraphs. It does not mark every bookmark in a paragraph as affected. Native TOC/PAGE/PAGEREF caches and instructions are preserved; no refresh or display accuracy is claimed. A08/A09 must surface and assess these warnings against the chosen engine.

## Explicit unsupported edits and acceptance boundaries

`EditException.getCode()` and operation ID identify rejection; there is no plain-text fallback. Unsupported cases include other story editing; zero-length spans; tabs/breaks or opaque inline features inside a replacement span; wrapped/non-direct text runs; paragraph field-content edits/clears; partial feature boundary deletion; section-bearing structural deletion or insertion style donors; vertically merged/final-row removal; nested editorial tables; unknown/macro/strict-namespace codecs; invalid controls or broken surrogate boundaries. Supported multiline body work uses explicit styled paragraph insertion, followed by source-bound text spans/clears/deletions from the generated index. A07 does not turn a flat whole-document textarea diff into structural edits.

Untouched XML/package preservation is mechanical evidence. It does not certify fonts installed on a deployment host, exact rendered page count after content removal, Word-open visual layout, field refresh, TOC accuracy, PDF conversion, business adoption, API preview/export snapshot identity or all-page final acceptance. Originals were never mutated, no document marker was rerun, and no server/database/browser/push/cleanup action occurred.
