## 已接入的代码

1. **目录先筛选。** `SourceDocumentRepository` 先读身份、角色、范围、状态和修订等字段，再仅加载入选文件的正文／结构／coverage／candidate 四项内容。两次读取之间身份变化会拒绝；不回退旧成功来源。来源资格未确认保持未确认，不把项目 PRE 误当 SL PRE 排除。
2. **来源摘要用于后续核验。** 数据库写边界维护四项内容摘要、组合摘要及 binding 原始快照摘要；活动语义 session 通过小字段、绑定历史及实际原件字节核验，不再每个阶段重新请求四项正文 LOB。没有可信摘要时只允许对选定来源受控冷准备，缺少触发器明确失败。
3. **冷准备也不把正文再次传回数据库。** 仅凭小字段 pins 锁定目标行并触发实际内容摘要计算，在同一事务内复读摘要，与调用方已经捕获的内容 hash 精确核对。不一致回滚，不把调用方声称的 hash 写成可信数据。不再将四项 LOB 或整份 binding 作为 UPDATE 的参数传回。
4. **PRE 原生身份重查入口。** `/api/evidence/{project}/documents/{id}/routing/native-recheck` 对 UNKNOWN DOCX 按需读有界原生段落与标题证据，拒绝旧原件、角色冲突、人工身份或排除范围；不 OCR、不读解析四项 LOB、不修改冻结审查输入。接口存在不代表线上 source101 已纠正。
5. **公共语义读取。** 复用 `/sources/read` 新的 prepare／semantic view。冷阶段沿现有来源解析及闭包生成 CAS 语义 manifest；之后 catalog、指定单元、有序 scan 不再重新 `registry.load` 或重建 `SourceUnits` 全图。实际 CAS／原件字节核验保留，不能声称这部分 I/O 消失。
6. **生产 caller 接通。** `VettingService` 使用 `loadSemantic → scan → rules → review`。原生规则／包身份上下文在持有完整核验帧时构建一次，随后使用副本；不能拿去掉位置的语义材料重建原生章节关系。
7. **模型消费语义材料。** 普通输入剔除坐标、XML 路径、版式和审计封存，保留原文、条件／例外、表格含义、编号、来源限制与 unknown。每个预准备 origin 有独立材料字典，不能引用另一个包才有的 `modelUnitRef`。引用用本包的 `R1…`，后台保留真实身份对应；只替换引用字段，绝不把相同字符串的正文或角色替换成引用号。冷帧已核实的条款标题位置另存服务器内部短标量，扫描后供原有归属门核验；不把位置送回模型，也不因压缩输入误拒正常的条款说明。
8. **全范围读取与比较分账。** 复用已有上下文及 source-request／token-aware 组包，传递公共闭包成员和联合对照。只实际派发的包计为提交；读完、空回答或一条 consistent 不能把整包判通过，缺失及未执行保留。
9. **意见后取原始定位。** 模型返回候选后批量取得相关原始 pointer，再执行 native／UTF16 事实绑定；准确原文但无物理坐标仍可保留，不猜第一处位置。重复共享的 evidence 对象只处理一次。固定 SL 等参考证据使用自己的核验链，不送入项目来源 binder。
10. **相同预检复用。** 同动作、同完整输入的成功 usage 观察可复用；仍检查取消、动作期限、配置和来源。失败或未知不复用，正式答案照原额度记数。

11. **规划停止与进度。** 额外包达到上限后不再为独立新包构造并付费预检，仍可测量能合入已有包的完整 union；遇到明确动作额度耗尽即停止后续 factory／observer，保留已有计划，其余记录未完成原因。没有测过的包不能标为已测量。阶段详情不再把较小的保存数覆盖已处理进度；保存数、失败数与未完成数继续分别显示。

同一动作内，完整输入相同的成功预检在内存中复用；重新打开 Operation 缺少完整观察时，持久账本按 action＋input 拒绝跨 phase 的再次预检付费，不将旧动作期限或额度重置。跨进程恢复完整观察仍未实现，拒绝重放不等于已恢复观察。

## 必须保留的成本与正确性边界

- 历史完整 binding／正文的第一次冷核验仍需要读取；没有做全库回填或迁移。新摘要安装与原件身份纠正是不同操作。
- warm 阶段保留实际原件／CAS 核验，也仍校验已经保留的语义视图。旧报告无活动 session 的守卫仍沿旧冷核验路径，不能声称所有报告读取已轻量化。
- 普通 Word 条件、续段和指导范围复用现有 Java 公共适配，并在冷阶段 memo；并非三模块全部已迁移到新读取方式。
- 全范围基础包与已有明确对照关系的执行，不证明所有潜在法律矛盾都已发现；真实漏报／误报仍须独立模型及业务验收。
- 源文件不同用途、版次和权限继续隔离；SL PRE、图纸、计价资料等原有排除规则保持。项目 PRE 需要身份依据，不能按文件名强行纳入。
- 本机 H2 与目标 MySQL 的安装路径不同。H2 inline trigger 必须在真实含 H2 的 JVM／服务端执行；MySQL 分支尚未真实运行。安装只增加列／触发器，不全表 backfill。
