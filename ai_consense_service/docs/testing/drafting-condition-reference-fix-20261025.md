# Drafting 条件引用、自身答案与图谱转换修复

日期：2026-10-25开始审计，2026-10-26完成修复与本机热修。对应本轮七类审计：正常答案路线误拦、编辑关联误报循环、真实循环漏检、合并新生自环、拆分条件／目标归属退化、来源核对身份分叉、重新识别同 ID 异义错绑。

## 本轮规则

- 独立填写／选择的变量可以用自己的已采用答案决定原文处理；这不是派生值循环。`false`、`true` 和未知分别求值，未知保留待核。
- 派生答案的条件／范围输入，以及记录子字段读取父记录的关系，构成实际取值依赖。编辑目标引用其他值不反向成为当前变量的取值依赖。真实自环与跨节点取值环必须拒绝。
- 来源核对事项保留原文与核查身份；改标题、改 role 或标为 manual 不会把 `source_seed` 自动转成可回答的业务变量。条件、范围、编辑取值来源均不能借它生成确定动作。历史非法图仍可读取，并通过修复后另存新修订。
- 合并预检检查替换 ID 后的真实取值图。拆分只在准确原件范围能唯一分配全部编辑目标时执行；保留原规则、外部前提、历史和待重绑状态，不按同一文件复制所有目标。拆分关系单独留作人工核对，不覆盖活跃业务规则。
- 重新识别遇到同生成 ID、不同业务定义时，保留旧人工节点和旧值，将本次完整原子响应保存为独立待核候选，完整重映射条件、父子、范围、修改取值、要求和关系。冲突明确标记 PARTIAL；稳定重跑复用同一候选，不静默接回不同含义的旧节点。

## 固定变量优先的实际链路与边界

用户本轮确认的流程方向是：优先对照内置固定变量和已有关系，先供人工确认；匹配不到或有歧义的单列审核调整。匹配上的定义也需人工确认，项目变量值采用另行保存。本次模板的适用条件、来源版本与准确修改范围仍须核对，旧位置和同名标题不能自动授权改文。

当前实现不是完整的“固定图谱优先归并”：

1. 自动识别先从当前模板原文形成动态图谱；新业务节点带 `catalogAlignment.status=unreviewed`。
2. 基准审核页面按名称规范化相等，以及类型、单位、选项、父子层级等兼容性给出匹配建议。它没有在模型识别前实施全面语义匹配，也未自动套入固定业务图谱。
3. 人工确认“匹配基准／新增／歧义”等定义对应；对齐记录参与定义指纹。基准补入复用字段定义形状，旧 `affects` 和原文坐标不当作当前模板的修改授权。
4. 已有动态图谱时，候选、采用、规划、快照与生成使用该修订的动态图谱；不会因 `baselineKey` 相同就切回固定规则引擎。
5. 历史无对齐元数据的节点仍可读取与继续核对。此次捕获的 Sean 草稿有203个业务变量，均无对齐元数据；本轮没有批量映射、迁移、确认图谱或采用项目值。

因此，“优先复用固定变量定义和已验证关系”可作为后续实现方向；本轮七类修复没有新增自动语义匹配或追加模型任务。固定目录继续作为可核对基准，而非自动证明所有同名条件／修改位置都相同。
