## Behavior and public contract

Generation copies each uploaded editable DOCX package through the A07 editor. The semantic editor emits source paragraph/whole-clause/insertion operations at the selected action seam; the compiler never diffs a completed flat document. It binds exact current source bytes, locators and paragraph expectations. Split-run replacements retain existing styles and controls; explicit multiline insertions clone an existing source paragraph/run donor. Known whole SCT/SCC heading adapters preserve the native clause-number tab and bookmark boundaries. Whole-clause scopes retain separate numbering cells, unrelated cells, page furniture and section geometry. A native OMML equation in a whole-clause scope is explicitly unresolved rather than leaving an orphan formula under an applied negative action.

The committed `guidance-compiler-bindings.json` is the independently curated source-bound sidecar: 194 nonempty text-only clears and14 guarded leading markers. Blank separators receive no operation. It is tied to original DOCX SHA-256 and exact descendant paragraph text/hash. Formal prefaces, adjacent contractual clauses and noncontiguous interleaved body text are retained. It contains no italic-style or generic delete-note heuristic. An unmatched uploaded edition keeps its guidance and returns `EDITORIAL_SOURCE_EDITION_UNVERIFIED` instead of pretending it was cleared. Inline contractual alternatives are changed only by adopted business operations. Unknown input values retain their existing unresolved content and alternatives.

All three generated packages are compiled before publishing any current pointer. `draft_artifact` stores immutable DOCX bytes, their source/DOCX hashes, shared input snapshot, operation ledger, current block projection, feature impacts and optional parent revision. `draft_document.revision_id` selects the current revision. Body saving appends a revision and refreshes content, digest and blocks from the emitted DOCX without changing the adopted input JSON/snapshot. Unsupported mapping failures and rejected saves leave prior artifact bytes/pointers intact. Original source files are never mutated. Contract identity remains snapshot metadata: these source templates contain no verified identity slots, so no cover, title or contract-number lines are added.

`DraftDocumentVO` adds `revisionId`, `docxSha256`, `sourceSha256`, `blocks`, `fieldStatus`, `fieldImpacts`, `pdfSha256` and `renderProfileHash`. Each block has `id`, `text`, `textHash`, `paragraphOrdinal`, `cellId`, `editable` and `unsupportedReason`. Block text includes native tabs and breaks. Catalog operations use A07 `replaceCatalogSpan` to safely map w:t-only offsets; body operations use editable-text spans. The two coordinate systems are never interchangeable.

The existing PUT `/api/drafting/{projectId}/documents/{fileKey}` accepts:

```json
{"revisionId":"current revision UUID","docxSha256":"current DOCX digest","blocks":[{"id":"current paragraph locator","expectedTextHash":"current block digest","text":"adopted paragraph text","insertAfter":["optional additional paragraph"]}]}
```

Only explicit changed blocks are submitted. A pessimistic refresh/lock and revision/hash/exact-text guards reject stale or replayed updates (`4090`). Invalid/duplicate/unsafe block operations return `4012`. Flat `content` replacement returns `FLAT_BODY_EDIT_UNSUPPORTED`; changed template-text PUT returns `SOURCE_TEXT_EDIT_REQUIRES_DOCX`. The user must upload the edited DOCX to change source text/format together. Legacy generated documents without a stored formatted revision remain readable and stale until regeneration. Existing input staleness remains `4009`. Template byte hashes participate in snapshot identity, including font-only changes whose parsed text stays the same.

Word export returns the stored exact DOCX bytes after hash validation. PDF preview/export call the A08C renderer on those bytes, cache immutable PDF bytes/manifest by DOCX SHA and assessed actual renderer profile, and publish PDF/profile hashes on document reads. Preview and export return the same cached PDF. Optional `revisionId` query guards on preview/export prevent a request for an old body revision from being fulfilled with a different current revision. No product route calls the plain-text Word/PDF writers. Field and font-selection status remain UNVERIFIED; affected field/bookmark data and pagination-review impacts are retained, and conversion does not certify field refresh.

Explicit configuration is `consense.drafting.renderer-executable`, `consense.drafting.renderer-work-root`, and `consense.drafting.renderer-timeout-ms` (default120000). Executable and work-root have no discovery/default fallback. Missing/invalid configuration, source font capability, timeout, invalid output and renderer failures return explicit `4013` capability messages. The profile is assessed before cache lookup using bounded actual-version probing, executable digest, locale and measured JVM-visible font-family inventory. Actual DOCX bytes plus that profile identity determine cache reuse.
