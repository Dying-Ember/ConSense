# DRAFT-A-12: extraction diagnostics in the existing Drafting controls

Date: 2026-10-06. Worktree base: `db79dac77e71a23306deaf22fed18a9c0e1d5d0c`. Spec: `drafting-extraction-harness.md`, requirements 10–13. Local implementation is verified; actual combined backend/7B/in-app-browser acceptance remains A13 work after A11 integration.

## Behavior delivered

The existing vertical input controls receive the latest additive trace. They show suggested, candidate disagreement, rejected, model-unanswered, omitted and unassessed diagnostics separately from the unchanged adoption/applicability status. Rejected, empty and omitted results explain that no usable suggestion was returned, without asserting absence of an answer in the source. Every referenced decision exposes its raw/normalized value, actual file/part/attempt/item identity, quotation, confidence and translated intake reason. Rejected diagnostic items have no adoption control. Original manual entry and existing candidate adoption controls remain independent.

The extraction-process modal shows completed/failed and stale outcomes, identity/revision, intake counts, full actual source parts and every recorded primary/repair attempt with exact prompts, response and failure code. Passing intake checks is expressly not business-fact validation. A five-field legacy trace remains readable without fabricating per-field diagnostics or a run outcome.

Project-scoped history uses bounded `GET /variables/extract-traces?limit=20` summaries and `GET /variables/extract-traces/{runId}` for a full report. A historical report has separate local inspector state; it never replaces the current trace, form values or adoption. Sequence, open-state, project and unmount guards reject late responses. Project changes close the modal. Historical read failures remain translated if the language changes.

When extraction fails, the view reads the latest current-run diagnostic trace while preserving its existing form values. If the read returns the same earlier run, or the diagnostic read fails, the earlier report is not relabelled as the failed call's report. The original extraction error remains visible. An available trace can also be opened from the source step.

Simplified Chinese, Traditional Chinese and English labels are supplied for all eleven agreed intake codes, field states, failure/staleness/history notes and process labels. Original English source text and values are displayed unchanged and escaped. Unknown future codes remain inspectable with an explanatory fallback; additional production codes require a specific translation before acceptance.
