## Delivered behavior

The common topbar offers `local` / `minimax-cn` in Simplified Chinese, Traditional Chinese and English, reads configured model/readiness from `/system/llm-profiles`, disables unavailable options, and distinguishes configuration readiness from connectivity/quota. Only `consense-llm-profile` is persisted in this browser. Valid unavailable preferences stay visible; unknown preferences resolve to the declared server default. Failed metadata reads retain a visible saved choice without claiming readiness or blocking deterministic/history reads. No browser credential or global server mutation was added.

The centralized client snapshots `X-ConSense-Llm-Profile` synchronously and preserves multipart, binary handling and existing timeouts. User actions capture a typed selection before the first await: Drafting saves/plan, Advice scrolling, and Vetting scheduling. An explicit null snapshot preserves header-absent legacy behavior even if the dropdown changes before a later request. New choices affect future operations. Backend worker/retry confinement is an A14/A16 responsibility, not established by frontend polling.

Additive `modelIdentity` types match the frozen safe DTO. Drafting reports/history, Vetting jobs and Advice replies/history use saved identities/model names; old records remain missing/unknown rather than acquiring the current selection. Configured identity is expressly not provider-attested execution. Native document compilation receives no fabricated frontend model identity. Business fields, adoption, generation rules, index contents and original checkouts were not changed.
