## 3 问题任务

### PRD01 自然问法的完整答案和流程图交付

**用户影响：**用户提出普通流程问题后，可能只得到处理中、部分正文或错误结束，没有可使用的图与最终答案。

**证据：**code07 的同证据包比较中，M3 在 16K 和 32K 生成额度均以 `length` 结束，没有完整最终正文；M2.7 两档均在最多一次修复后未满足 JSON／应用契约。没有接受的最终图或答案。隔离图组件的准备和构建完成，不代表实际业务图已显示。[E1、E2]

**处理方向：**沿现有 T6 图计划、校验及渲染接缝定位。分别检查生成终止、完整对象提取、图结构、引用语义、渲染和最终保存。graph-first 或调整单元组织属于待验证候选，不是已经证明有效的修法。

**验收：**

- 原普通 Q1.6 问句能交付实际可显示的图与完整最终答案，来源、路径质量另行通过 PRD02。
- 普通中文短问法及另一类自然图问题分别执行；题型间的成功不能继承。
- 空正文、未接受草稿、`length`、取消和后置失败均不能出现虚假完成或成功历史。
- 使用通用图计划和来源规则；官方答案、题号特判和私有纠正图不进入生成端。

### PRD02 引用支持与合同流程语义

**用户影响：**回答看似有引用，实际可能引用标题；流程图也可能给出错误期限、权限、分支或终局效果。

**证据：**M2.7 首次 raw 草稿的独审发现：选定的 38 项条文要点全部在实际发送包；45 条具有合同含义的引用行均仅引用标题，正文支持行为 0。图中有 3 个不可达节点及 3 条无 actor 动作，另有 final/binding 范围扩张、虚构期限触发、绕过 CM 阶段及分支方向反接。上述是该草稿的条目／行数，不是独立缺陷数或模型准确率。[E2、E3]

**归因边界：**这些具体残差已经在 raw 中，不能归为前端改箭头或选定文字未送入。仍需对照区分模型、prompt、模式和证据表达；该模型是 M2.7，不能将结果填入 Qwen3.8-27B 的能力格。

**处理方向：**为命题与引用建立来源核查；分别评价每个条件、例外、角色、期限起算、终点和关键分支。复用已有引用身份与图结构门，独立语义审核补其不能判断的部分。模型 R1–R10 自报 pass 不单独授予法律正确。

**验收：**

- 引用可回到真正支持该命题的正文／表组；标题存在和 ID 合法不足以通过。
- 时限、起算事件、角色权限和分支方向有逐项来源证据；修订和例外保持实际作用范围。
- 保留近似但不冲突、及时／逾期、实际采用未知等反例。
- schema／图结构、命题／引用语义与完整覆盖分项报告；放宽字段校验不改变内容评分。

### PRD03 Vetting 完整输入和审查覆盖

**用户影响：**用户难以判断“零发现”是没有问题，还是资料没有真正完成审查。

**证据：**旧 job `97ca407a-1fa3-48b0-a1d2-bc884e7574ab` 持久化为 COMPLETED，但 17 个 topic 均为 partial。119 个 planner 补充来源请求均未提交，原因为 `no_bound_token_observer`／`not_submitted_budget_unknown`；它们不是模型反复索要的119次工具调用。唯一已提交片段46个，范围仅为局部 GCC／SCC。[E4]

**当前边界：**已有 Responses 同 wire 计数／生成绑定路线；是否在实际 Vetting 构建与配置启用、是否完成新业务复测，本调查未验证。旧结果不能追认为修复后通过。

**处理方向：**确认实际模型、wire、完整请求与预算观察器绑定；区分 planned、submitted、model-returned、mechanically-accepted 和 independently-reviewed。复用现有 coverage，不新增另一套完成率。

**验收：**

- 完整相关材料有实际提交证据；未提交、缺证、超预算和失败均保留可见状态与原因。
- 模型与实际序列化请求绑定，观察不明时保持 unknown；其他 tokenizer 或字符估算不能冒充真实计数。
- “任务执行结束”“完整范围审查完成”“零发现”“独立判断无问题”分别表达。
- 以独立应发现集合和合理无问题反例评价关键漏报／误报，不能只审已返回 finding。

### PRD04 思考 输出和接口契约

**用户影响：**等待增加却没有完整答案；修复请求可能再次产出非法 JSON 或违反单元契约。

**证据：**M3 adaptive 的 16K／32K 比较均触顶；M2.7 增至32K仍有 JSON、scope、gaps 和 actor 等拒绝。该固定包 runner 的 `contextMeasured=false`、`providerUsage=null`，使用字节启发式准入；不能把 `204133`称为实测输入 tokens。每个 section 的十项检查及结构化图字段确有协议负担，但尚未证明其导致思考耗尽。[E1、E2、E5]

**处理方向：**先捕获实际调用的完整输入与终态，分别测总窗、思考模式、生成额度和契约组织。一次只改变一个因素。协议精简保留既定角色、时限、条件、引用和发布门；M3 disabled／更高额度等未执行方案按实际授权另列。

**验收：**

- 对已授权实际调用记录模型／模板／prompt版本、完整请求 hash、准确或明确 unknown 的输入／输出 usage、reasoning 配方、输出上限、stop原因及修复次数。
- 思考与最终输出按准确引擎计入总窗口；新的准入估算明确标为估算。
- Qwen 的实际 `reasoning_effort` 被引擎消费；stable M3 的 adaptive 与 Flash 的 effort 控制分别记录。
- 同材料／同契约比较最终交付和来源质量，思考更长、预算更大不自动算改善。
- 256K／512K仍是现有选型范围；窗口、字节数、KV驻留和有效注意力范围各自核验，不以扩大到1M代替归因。

### PRD05 完整原件阅读和定位

**用户影响：**点击引用后，用户可能只能看摘录，或无法确认实际原件中的对应位置与邻文。

**证据：**完整 PDF／DOCX 接口和阅读接线已实现。旧真实 PDF sample 的完整文件、物理页和邻页已读取，无精确几何高亮时有 warning；该 sample 不能替代新版图引用。真实 citation→完整 DOCX→唯一节点／部件／邻文的浏览器链尚未通过。[E1]

**处理方向：**按 CitationVO 实际来源身份复用现有阅读组件，分别验 PDF 物理页、DOCX part/native位置和整表上下文。历史来源失效保留失败，不重绑同名新版。

**验收：**

- 使用真实已接受引用打开完整实际源文件；内容 hash、版本、位置与引用一致。
- DOCX 唯一节点／部件和前后内容可阅读，完整表组不被局部摘录替代。
- 位置未知、无几何或材料失效有真实提示，不能制造页码或高亮框。
- PDF sample、新图引用和 DOCX 三项分别报告，不继承通过。

### PRD06 有限分析 历史和实时交互

**用户影响：**部分有据内容、缺证补问、停止和最终完成之间的状态，可能与用户看到的正文／历史不一致。

**证据：**有限分析、真实 streaming、业务事件、取消与应用持有已发布前缀已实现。旧 run04 的后置修复改前缀问题已推动修补，不应再列成当前未修 bug；完整成功历史、缺条件自然题、真实发布时序及会话／来源竞态仍未全面通过。[E1]

**验收：**

- 缺部分依据时保留经验证的有限分析和真实引用，显示受影响判断与必要补问；整体不足状态保持真实。
- 已发布单元不被后续修复改写；最终组合仍核身份、范围、采用、语言和引用。
- complete只在最终原子保存成功后发送；失败／取消不写成成功答案。
- 用真实已授权链路分别验证停止、断线、迟到事件、项目／session切换、稳定滚动和来源联动。
- 自检保持内部记录；新增自检 UI 不属于既定首版要求。

### PRD07 OER 正常链与下游消费

**用户影响：**原件内容虽被某个工具观察到，正常上传产物或 LLM 发送包仍可能丢失关系、条件或整组内容。

**证据：**历史 Q1.6 的 canonical 已有正文与 parent 关系，retrieve却主要返回标题，缺口在候选与闭包消费。当前[引擎整合规格](oer-engine-integration-repair-20261014.md)另已确认正常入口的观察、身份、布局传输、混合页补读及完整结构组合仍需闭合；身份与弱metadata提示首批修复已记录，不能重复当未修项。[E6、E7]

**处理方向：**与 ENG 任务共用同一责任分界。分别核原件→parser→canonical→索引候选→结构扩展→实际wire；输入缺口优先在首次丢失处修。读取其最新任务状态后再决定是否新增工作，避免平行改同一引擎。

**验收：**

- 正常上传原件的完整范围、表单类型／状态／值、表格与跨页关系有独立来源核验。
- 条件、例外、整表与来源角色在下游实际包中保持，实际正文缺失不能由身份／schema通过代替。
- loss、JSON合法、索引ready、局部正确和人工投影不授自动正常parser或整库质量通过。
- 图纸仅身份路由后排除；范围内文字引用不按drawing/BQ关键词误删；Drafting模板及2d/2e答案继续隔离。
- OER训练候选的采用、重建和业务测试均绑定新身份；不覆盖旧失败或切换活动基准。

### PRD08 业务归因和模型采用证据

**用户影响：**团队无法可靠决定该修引擎、改harness、训模型还是换模型；代码合并可能被误解为产品已经可用。

**证据：**当前新对照是固定来源能力比较，尚非fresh retrieval／真实项目session／前端完整业务。Qwen3.8-27B没有本轮新版Vetting／Advisory同材料成绩；Drafting可用、M3或M2.7结果不能补入其能力格。目标MySQL迁移、Linux／H800与生产切换仍有未验门。[E1、E5]

**处理方向：**复用现有捕获与评分入口，按同题固定四类输入：来源审核后的完整材料＋最小清晰契约；同材料＋生产harness；正常parser对应产物＋同harness；实际RAG发送包＋同harness。业务义务和评分保持一致。固定raw重放另评接收层。

**验收：**

- 每个错误指出首次出现层、支持证据和仍未知因素；交互因素不相减为三个错误百分比。
