## Result and scope

`DraftExtractionHarness` owns the Drafting-local compact native-value protocol, one schema projection, local legacy-compatible decoding, explicit attempts, item intake decisions, narrow literal identifier checks and bounded targeted repair. The shared `AiGateway`, provider, structured validator, model/context configuration, 21-group/79-field business catalogue, business normalizer and clause generation are unchanged. The default configurable prompts no longer repeat the catalogue/input contract. Customized system/user text is retained; complete source text is appended once with real line delimiters even when a custom user template has zero or one placeholders. The contract extraction projection permits supported partial siblings without changing the UI/generation completeness requirements.

All source parts are frozen before dispatch. Each returned item has accepted/rejected/unanswered status and the agreed reason codes. Accepted intake does not certify source entailment. Contract number/title and supplied Bill number/description must occur in that same source part under existing whitespace/typographic quote normalization. No generic Boolean/enum truth judge or SIM-specific production logic was added. Native null and legacy serialized null/unknown are distinct from false and an explicit empty list; literal numeric-looking text remains text.

Primary syntax/mapping failures permit one retry. Known nonblank shape/quote/literal failures with acceptable confidence permit one targeted repair. Already accepted keys are excluded; repair output outside the permitted keys is rejected. The maximum is two primary attempts plus one repair per part, with exact effective prompts/raw response retained. Failed repair does not retry implicitly and leaves original rejections visible. A malformed primary exhausts its two attempts and fails without partial candidate writes.

`draft_extraction_run` is an immutable final-record entity with V8 migration. Success report insertion and candidate changes share one transaction; failures append a separate report after rollback. Latest trace retains all five legacy fields, plus the agreed diagnostics. History is bounded to default 10/max 20, project scoped, read only, and calculates source staleness without rewriting stored identity. The public endpoints are `/variables/extract-trace`, `/variables/extract-traces?limit=20`, and `/variables/extract-traces/{runId}`. Null raw values are explicitly included after persisted-report deserialization despite the application's general non-null JSON setting.

Source upload/delete and the brief final extraction transaction acquire the same project-row lock before variable locks. Batch DOCX parsing/storage happens before acquiring that lock; model calls remain outside write transactions. The existing evidence revision check runs while holding the project lock. Concurrent manual edits are refreshed and preserved. Candidate-disagreement diagnostics are independent of manual/adopted state.
