## Observable behavior

An actual dispatched answer returns and persists safe configured `modelIdentity`; reading history under another selected profile returns the original identity. Older messages remain missing identity. Nullable `V10__advice_model_identity.sql` adds the column without rewriting old rows.

Explicit unconfigured model actions fail visibly before index availability can obscure the configuration error. When evidence requires chat, an unavailable selected provider visibly fails instead of becoming a no-evidence answer or switching provider. A thrown provider exception is represented by safe profile/type information; external exception text is not exposed by Advice. Failed transactions leave no apparent successful/user-only answer history.

Fixed deployment embeddings remain separate from selected chat availability. Public index rebuilding with MiniMax unavailable still uses the local embedding adapter; subsequent model-needed Advice fails visibly. Required fixed embedding unavailability also fails visibly with no cloud embedding/chat dispatch. Header-absent Advice retains the deployment chat path. Genuine no-hit retrieval remains a deterministic no-basis answer and carries neither a chat model label nor model identity because chat was not dispatched. A no-basis response produced by a dispatched model retains its configured identity.
