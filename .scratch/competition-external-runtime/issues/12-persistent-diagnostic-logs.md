# 12: 让一次操作留下可排错的持久日志

**What to build:** 使用者或排障人员能根据一个请求或任务编号，在硬盘日志中定位一次完整操作的阶段、失败或取消原因，同时原始证据得到独立保护。

**Blocked by:** 07 — 让本地回答逐段展示并能真正停止；09 — 让新资料完成建索引、查询和原文回查。

**Status:** ready-for-agent

- [ ] 在本机实际容器链完成成功、失败和取消的代表性操作，使用已有请求或任务编号关联浏览器、业务、资料、显卡任务与模型阶段。
- [ ] 日志记录必要的开始、结束、耗时、错误类别、结果完整状态及代码、配置、模型身份，能由人手判断问题发生在哪个边界，不另建全链日志平台或额外容器。
- [ ] 日志写入登记的持久目录并按实际运行用户权限可读，重启容器后仍能定位同一操作，镜像内临时文件不成为唯一记录。
- [ ] 普通日志默认不含密钥、认证头、原件全文或完整模型答案；检查异常、地址和子进程输出中的实际泄露路径，并对诊断记录脱敏。
- [ ] 普通日志和必要原始证据分别管理，轮转不能删除来源、失败或任务结果证据；普通日志故障与关键证据保存失败采用各自规则。
- [ ] 在预演专用位置实测权限不足、轮转和磁盘不足，不能伪报任务成功、错误放行后续显卡任务或影响无关活动数据。
- [ ] 保存日志关联、脱敏及受控故障证据，提供人手按编号找日志、确认失败阶段、检查磁盘和恢复写入的步骤。
