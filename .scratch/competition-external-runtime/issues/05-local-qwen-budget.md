# 05: 通过外置配置将现有 Qwen API 切到本机 vLLM

**What to build:** 保留现有 Qwen 客户端和兼容 API，通过外置配置把官方 API 地址切到本机自部署的 vLLM，使用现有业务请求验证实际本地 Qwen3.8 27B 调用和必要预算配置生效。

**Blocked by:** 04 — 从硬盘执行显卡任务并统一控制占用。

**Status:** ready-for-agent

- [ ] 通过外置配置把现有 Qwen 调用从官方 API 地址切到本机 vLLM，核对兼容 API 根地址、现有模型名及实际需要的认证；优先保持客户端、请求和返回约定不变，思考关闭、业务并发沿用现值。
- [ ] vLLM 使用登记的真实 Qwen3.8 27B 权重和配套文件，经前票统一准入在共用预演容器环境运行；核对实际加载身份，不额外并行拉另一套显卡实例，不用小模型、外网或假响应完成本票。
- [ ] 记录配置覆盖顺序、加载时机和脱敏有效值，以一次现有业务真实请求证明地址切换已经生效；上下文、输出预算和超时只按实际服务能力配置，不新建模型调参功能。
- [ ] 沿现有实际调用验证聊天、结构化结果和输入计数；Responses 仅在调用链实际使用时检查。先确认兼容协议能否直接工作，只有实测不兼容时才按证据最小修复，不重新选择框架或预先重写通用适配层。
- [ ] 用代表性实际业务输入核对真实计数来源和输入输出预算，配置不生效、模型名错误、缺权重或超出实际预算时明确失败；不以伪造计数、静默关闭原能力或转向外网过关。
- [ ] 按本机实际资源完成 vLLM 请求，记录权重和运行配置身份及资源表现；不默默改变已确认的权重或精度。资源不足继续解决或保持未完成，同时推进可独立票。
- [ ] 分别保存配置切换、真实本地权重加载和实际请求证据；软件协议检查只能辅助，不能以留待比赛现场为由关闭本票。
- [ ] 写明人手检查地址、模型名、认证、有效配置和 vLLM 服务状态的步骤，秘密保存在受限私有位置。
