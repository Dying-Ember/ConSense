# 13: 在隔离副本恢复受搬迁影响的历史项目

**What to build:** 使用已有恢复方式，在本机隔离副本中恢复受本次搬迁影响的持久数据库、原件、索引、人工记录和生成文件，并从真实业务入口读回。

**Blocked by:** 09 — 让新资料完成建索引、查询和原文回查。

**Status:** ready-for-agent

- [ ] 根据本次实际变动确定恢复范围，使用数据库支持的一致性方式取得副本，登记副本、关联资产和恢复点；不直接覆盖或搬动活动数据库和原件。
- [ ] 在本机预演专用数据目录与容器实例中恢复选定持久关系数据库及向量数据库，不以 H2 内存或内存向量库替代选定运行方案。
- [ ] 通过真实浏览器及业务接口，读回历史原件原页、来源版本、人工核对和备注、索引、报告及生成文件，验证实际关联而非只比记录或文件数量。
- [ ] 历史绝对路径、不同容器视角和权限经过实际验证，读到的文件字节及项目身份正确，失效路径不会指向其他项目或新版本。
- [ ] 容器退出重建后再次读回代表性历史项目；来源、模型及索引身份匹配，不将恢复成功误记为模型质量或业务判断通过。
- [ ] 恢复失败和缺资产时留下真实证据并保护现有副本，不通过删除历史或重新生成内容掩盖缺失；本次不无条件新建备份系统或数据库迁移工程。
- [ ] 保存实际恢复、页面重读和重启检查证据，写清人手准备副本、恢复顺序、核对关系及失败处理步骤。
