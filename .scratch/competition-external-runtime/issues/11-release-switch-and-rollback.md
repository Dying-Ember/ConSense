# 11: 受控换版并在失败后恢复

**What to build:** 在允许的短暂停机内处理好进行中任务，切换完整新版本；新版本失败时能按经过演练的顺序恢复可用程序、数据及历史访问。

**Blocked by:** 10 — 离线修改代码并产出可运行的新版本。

**Status:** ready-for-agent

- [ ] 对本机预演专用实例实际执行一次完整换版，切换前明确完成、取消或保留进行中任务，已保存草稿、人工记录和结果不丢失。
- [ ] 每个请求固定对应完整版本，新旧程序、导入模块、子进程、配置和模型引用不交叉混用；旧网页仍能取得自身必要资源。
- [ ] 实测版本切换、新旧实例退出及失败恢复全过程的容器数量，始终不超过五个，不依赖只读挂载或一次检查作保证。
- [ ] 故意引入可控的新版本启动失败，按实际步骤恢复旧版本，验证原数据、历史引用、旧网页和已有结果仍可读。
- [ ] 若实际涉及数据库结构变化，在隔离一致性副本验证程序与数据回退条件；不假定换回旧程序等于数据库已回退，不无条件新增迁移工程。
- [ ] 切换与恢复只操作登记归属的实例、任务和数据，保留无关活动服务；失败及未完成任务保持真实状态。
- [ ] 保存实际换版、故障、恢复和业务重读证据，并给出人手可执行的正常更新、失败判定和回退步骤，不声称无停机或未经验证的热更新。
