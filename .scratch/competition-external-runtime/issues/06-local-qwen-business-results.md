# 06: 让本地 Qwen 完成现有业务请求并保存结果

**What to build:** 使用者从现有页面发起业务请求，经实际容器链调用本机 Qwen3.8 27B，取得所需普通或结构化结果，并在持久数据库中保存和读回。

**Blocked by:** 02 — 从硬盘启动后端和完整网页；05 — 通过外置配置将现有 Qwen API 切到本机 vLLM。

**Status:** ready-for-agent

- [ ] 以真实项目隔离副本，从现有业务入口发起代表性的普通与结构化请求，经登记的实际容器链调用本机真实 Qwen 权重。
- [ ] 请求经过业务、协调及模型边界时保留项目、来源范围、任务、输入及版本身份，结果对应原请求和实际执行任务。
- [ ] 现有结构化结果验证、错误处理和来源守卫保持有效；未通过验证的内容不能当成成功结果保存或展示。
- [ ] 模型成功、错误、超时和格式失败到业务接口及页面后保留正确含义；不静默改用外网服务，也不将底层失败包装成空的成功回答。
- [ ] 成功或失败结果及真实完成状态写入选定的持久数据库和证据位置，重启所属容器后通过页面读回，历史记录不依赖进程内存。
- [ ] 记录实际模型调用、请求响应身份和数据库重读证据；协议替身只用于有限错误分支检查，不替代本票的真实模型业务调用。
- [ ] 对本次改造引入的退化完成修复并保留失败证据；基线原有的法律判断或模型质量缺口按原状态记录，不恢复已取消的全面整改。
